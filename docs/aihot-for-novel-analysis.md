# AIHOT 架构分析：给"AI 小说自动学习系统"的参考

> P0 交付物 · 2026-10-16
> 分析对象：https://github.com/KKKKhazix/AIHOT （7.9k star，MIT，TypeScript）
> 结论先行：**不搬它的代码，搬它的机制。** AIHOT 90% 的表面积是网站（React 前端、
> RSS/MCP 出口、admin 后台），与小说 MVP 无关；真正值钱的是它的**编辑流水线设计**：
> 判重、预筛、双评分、归组、独立来源热度、回执熔断、评测校准闭环。

## 0. AIHOT 是什么

一个"自己找热点、自己写日报"的网站框架：六种信源（RSS/网页/JSON API/X/公众号/
外部推送）→ 判重抓原文 → 预筛 → 双评分 → 结构化 → 中文标题摘要 → 聚成事件 →
按事件算热度 → 规则汇编日报/周报/月报。换信源和提示词就能换成任何行业的站点。

技术栈：Node 24 + TypeScript + Fastify + React Router SSR + PostgreSQL + pg-boss
任务队列 + Docker。三进程（api/worker/web），页面永不调模型，模型只在 worker 里调。

## 1. 可以直接借鉴的模块（设计层面照搬）

| AIHOT 机制 | 做法 | 对小说系统的意义 |
|---|---|---|
| 信源分级 + 分级门槛 | T1 官方一手 / T1.5 核实过的准官方 / T2 媒体个人，不同门槛入选 | 小说信源同样分级：官方榜单=T1，出版社/作者官微=T1，书评媒体/百科=T2，论坛讨论=T2。榜单数据可信度天然高于论坛 rumor |
| 判重 | 同 URL、同内容只留一份；正文相似再判 | 资料采集第一道闸，直接复用 |
| 预筛 prefilter | 宽进只拦明显无关（BLOCK/PASS/UNKNOWN）；材料不足先挂着不评分 | "这份资料是否关于目标小说"的便宜预筛；只有标题没有正文的先等材料，不浪费模型钱 |
| **双评分** | 同一评分标准独立打两次，两次之和 ≥ 2×门槛才过 | "这本小说值不值得学"的抗噪核心。单次 LLM 评分噪声大，双评分 + 门槛是我们 PopularityScore 里"值得学维度"的翻版 |
| 结构化 structure | 评分同时抽：分类/标签/主体/事实（谁-做了什么-对什么-何时）/前提 | 资料级结构化直接照搬：这份资料讲的是哪本书的哪个方面（人物/剧情/设定/销量/争议），有没有具体事实 |
| 归组 grouping | 向量召回近两周候选 → LLM 判四种关系（SAME_OCCURRENCE 同一次发生 / SAME_STORY 同一事件进展 / UNRELATED / ROUNDUP 汇总稿）→ 置信度门槛 + 复核模型 | 解决用户明确提出的"100 篇转载 ≠ 100 份资料"：同书书评聚类、转载去重、书单盘点文（ROUNDUP）单独处理 |
| 独立来源热度 | 按"事件"不按"文章"算热度；48h 内每个独立来源计一次，24h 减半；爬虫重复不膨胀；标注 rising vs 6h 前 | NovelPopularityScore 的骨架：多榜单出现次数 + 独立讨论平台数 + 近期增长，而非迷信单一榜单 |
| 评测校准闭环 | gold.jsonl 人工标注 100~200 条 → eval 脚本出准确率/查准/查全/F1/覆盖率 + 门槛扫描 40~90 → SelectBench 看错例 → 改提示词不改门槛 → dev/holdout 防过拟合 | Dataset Quality Gate 和"值得学"判断的校准方法，整个照搬。这是 AIHOT 最被低估的部分 |
| 回执 + 预算熔断 | 付费请求先记回执，结果先存再用，重试复用不重复花钱；每分钟/时/天预算上限超限暂停 | LLM 调用层直接照搬：小说理解会烧钱，回执防重试双倍扣费 |
| 提示词版本 = 内容哈希 | 改提示词只影响之后的新资料，已判过的不重算 | 知识抽取 prompt 迭代时保持知识库稳定 |
| 人工修正永不被覆盖 | 后台改过的分数/归属，自动流程不再碰 | 知识库人工纠错后不被下一轮流水线冲掉 |
| 旧文不刷屏 | 发现时已超 48h 的按原文时间归档不进"今天"；无可信时间先不公开 | 对应"完结老书 vs 当期新书"分流；无日期资料不进热度计算 |

## 2. 需要改造成小说场景的模块

1. **信源读取器**。RSS/网页/JSON 读取器思路可用，但首批信源完全不同：
   榜单轮询（番茄引擎已建成，74 板块）、平台书页、公开百科、书评站点、
   知乎/贴吧讨论页。X/公众号读取器 MVP 不做。
2. **"事件"概念 → "资料簇"**。AIHOT 聚类的是新闻事件（同一次发生）；
   我们聚类的对象是"关于同一本书同一侧面的资料"。映射：
   SAME_OCCURRENCE ≈ 同一篇的转载；SAME_STORY ≈ 同一话题的后续
   （连载进展、新讨论）；ROUNDUP ≈ 书单/盘点文。
3. **评分标准**。新闻重要性 rubric 整个重写为"值得学习值"：
   题材代表性 × 热度 × 口碑 × 写作特征可提取性 × 资料充分度。
   阈值照样分级（官方榜单来源的书门槛低一些）。
4. **写作层 → 知识抽取层**。AIHOT 的"中文标题+答案先行摘要+推荐理由+防幻觉
   公司名护栏"，改造成"人物/关系/事件/设定的 JSON 抽取 + 防编造护栏"
   （抽不出就返回 UNKNOWN，禁止模型补全剧情）。AIHOT"写坏了只重写措辞词表
   一次"的 mend-wording 思路可借鉴为"抽取字段失败只补该字段"。
5. **热度公式**。独立来源计数保留，但输入换成：多榜单出现、独立讨论平台数、
   快照间在读增长（我们已有 data/snapshots/ 底座，AIHOT 没有的跨期对比）。
6. **日报汇编 → 学习简报**。"规则汇编不调模型"的原则保留：知识库更新周报
   用规则生成，模型只写导语。

## 3. AIHOT 没有、需要我们自建的模块（本项目核心增量）

1. **Novel Understanding 深度抽取**。AIHOT 的结构化只有新闻级五元组；
   我们需要人物（身份/性格/目标/能力/关系）、世界观（规则/地点/组织/力量体系）、
   剧情 Timeline→Arc→Event→Conflict→Resolution、人物关系图、写作风格
   （叙事视角/节奏/对白比/描写偏好/悬念手法/伏笔反转）。这是最大的新建模块。
2. **Novel Knowledge Base**。不是 Markdown 堆，是带溯源链的实体-关系库：
   每条知识 → 支撑文档 → source_url（继承 AIHOT"来源可追溯"+"事实证据条件"
   原则，禁止模型凭空创造事实）。MVP 用 SQLite 即可，不必上 PostgreSQL。
3. **Rights Gate（版权门禁）**。AIHOT 做新闻聚合没有训练语料问题；我们有。
   每份资料带 rights 字段（open_license / authorized / user_provided / metadata_only），
   **训练数据只能从合法语料生成**；榜单元数据和书评分析可以进知识库，
   受版权正文不进训练集。这是与 AIHOT 最大的架构差异，不可妥协。
4. **Dataset Factory + Quality Gate**。六类样本（问答/人物分析/剧情理解/世界观/
   长文总结/写作任务）自动生成 + 格式检查 + 重复检查 + **事实一致性校验
   （答案必须能在知识库溯源）** + train/val/test 切分。评测校准方法借鉴
   SelectBench，但指标对象是"样本是否事实正确"而非"新闻该不该选"。
5. **风格量化器**。句长/段长/对白比/更新节奏的统计画像（已建成
   `research/style_mining.py` 种子）。AIHOT 完全没有。
6. **LLaMA Factory Adapter**。训练出口，AIHOT 无。

## 4. 数据流映射：AIHOT → 小说自动学习流水线

```text
AIHOT                                小说系统
─────────────────────                ─────────────────────────────
信源（RSS/X/公众号…）                 信源（榜单轮询✓已有/书页/百科/书评/讨论区）
        ↓                                    ↓
采集·判重·抓原文                       Discovery（榜单→候选池✓已有74板块）
        ↓                                    ↓
预筛 prefilter                         PopularityScore（多榜单独立计数
        ↓                               +快照增长+书评量）→ Top10
双评分（×2，门槛）                             ↓
        ↓                            资料采集（合法公开：简介/书评/访谈/
结构化（五元组）                         百科/公开章节）→ 判重 → Rights Gate
        ↓                                    ↓
标题摘要写作                           Prefilter（是否关于目标书）→
        ↓                               Structure（哪个方面+事实五元组）
归组（SAME/STORY/UNRELATED/                ↓
       ROUNDUP）→ 事件 → 热度          Knowledge Extraction（人物/剧情/
        ↓                               世界观/关系/风格，双评分+防幻觉护栏）
        ↓                                    ↓
publication 单一读取层                  Novel Knowledge Base（溯源链）
        ↓                                    ↓
日报/周报/月报                          Dataset Factory → Quality Gate
                                              ↓
                                        LLaMA Factory（SFT/LoRA/QLoRA）
```

已有的种子：`research/discover.py`（74 板块轮询+快照）= Discovery 层；
`research/corpus.py`（rights 门禁）= Rights Gate 雏形；`research/style_mining.py`
= 风格量化器；`research/report.py` = 学习简报雏形。

## 5. 技术选型判断

- **不 fork AIHOT、不用它的代码**。它是 TypeScript+PostgreSQL+Docker 的网站框架，
  我们是 Python 数据管线；强行套用等于先背上三进程网站运维再写逻辑。
- **机制用 Python 重实现**，MVP 存储 SQLite + JSONL 文件，任务调度用 cron/
  APScheduler，不引入 pg-boss/Docker。规模到了再迁移。
- AIHOT 值得"整段抄"的是三份思想：`selection.md` 的校准方法论、
  `grouping.md` 的关系四分类+评测、`architecture.md` 的不变规则
  （页面不调模型/花钱有回执/人工修正不被覆盖）。
