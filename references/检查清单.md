# AI写小说硬性检查清单 v1.0（公开版）

> 来源：微软研究院 ConStory-Bench 论文（arXiv:2603.05890）五大失误类型 ＋ 作者首本书 1-12 章实战踩坑 ＋ 作者亲口定调。
> 每章终稿前逐项过，grep 验证。
> 公开版说明：书内专属设定（人名、数值、伏笔）已替换为通用表述；具体数值以你项目的设定集为准。

## 零、主角性格铁律（韩立式）
- [ ] ⑩条行为清单逐项自查（贴在你的设定集里）：
  ①留三手 ②不轻信（包括盟友） ③先算计后行动 ④分散风险 ⑤闷声发财
  ⑥不赌运气 ⑦提前想跑路 ⑧躲人后 ⑨利己不伤人（稳、无后患）
  ⑩**智商≠预知未来**：每个判断必须有前文依据链，不许"她就是知道"
- [ ] 做事躲在人后：露脸的事让盟友/配角去，主角只递结果
- [ ] 出发前想好退路：物理跑路＋话术跑路＋关系跑路
- [ ] 没有仁义道德口号，全是利益和算计；但不损己前提下可做好事（稳、无后患、不留尾巴）
- [ ] 重要配角：各有所长、性格稳定，不降智不抢戏

## 零点五、文章要求（番茄小说女频末世文）
- [ ] 2000–2400 非空白字符/章（初稿可超，终稿收敛；以项目口径为准）
- [ ] 去AI味：不用"不由得""忍不住"堆砌，不用排比喊口号
- [ ] 对话：短、硬、藏信息；主角说话不超过两句，点到为止
- [ ] 心理活动：只写"看到→想到→决定"三步，不写上帝解说
- [ ] 钩子：每章末留一个，不许平收
- [ ] **全员智商在线**：不是只有主角聪明——配角各有城府；
  主角只是更低调、更苟、更谨慎，智商高"一点点"，靠信息差和准备赢，
  不靠对手降智。反派不许突然变蠢，正派不许突然圣母
- [ ] **每次交锋只赢一点点**：主角和对手过招，每次都是险胜——
  赢在信息差、赢在多准备一步、赢在对方不知道她知道；
  不许碾压，不许"她早就算到了一切"式全知；
  每次赢完都要有代价/新麻烦，保持"惊险刺激"的阅读张力。连赢三章必安排一次被动
- [ ] **剧情推进合理**：每个转折必须有前文铺垫，拒绝"天降""巧合""突然"；
  对手出招要有动机，主角接招要有依据链（呼应第⑩条）
- [ ] 无CP线、无圣母；对手的"谨慎"是长期人设，不许突然变蠢
- [ ] 汉字：正文/细纲不用英文缩写、不用拼音（Ch11→第十一章）
- [ ] 标点：全角中文标点；时间 19:39:52 这类数字和既有代号可半角

## 一、人物一致性
- [ ] 人名统一：grep 全文，同一人物只有一种写法（老张≠老章）
- [ ] 年龄、称谓前后统一（"五十多岁"不能变"四十多岁"）
- [ ] 人物关系与空间位置统一（谁住谁对门，不是楼下，全书一致）
- [ ] 出场介绍口吻：第二次见面不写成初见（"还是那两人"≠重新介绍）
- [ ] 性格锚点：主角行为清单⑩条逐项自查（设定集）

## 二、时间线与情节逻辑
- [ ] 时间线连续（D+数字或纯汉字天数，全书统一一种），无跳跃、无倒流
- [ ] 周期性事件的规律全书一致，时间戳变化符合设定（如有逐次提前/延后，前后吻合）
- [ ] 精确到秒的时间必须给来源（实测值："秒针跳到52，她抬头"；不能空降预测值）
- [ ] 天气/天文作为推理依据时，必须写她"查过""记下"（不能空降"那天阴"）
- [ ] 资金流：先付后验，无"尾款"；钱走可信中间人，不经主角的手

## 三、世界设定
- [ ] 能量/资源来源规则唯一且自洽（什么能充、什么不能充全书一致；对方违反规则=破绽，不是充能）
- [ ] 补给/恢复只发生在设定允许的窗口（白天不可能的事别发生在白天）
- [ ] 衰减/消耗速率固定，已损失的不逆转
- [ ] 空间类金手指：体积、时间规则、冻结条件以设定集为准，正文不许私改

## 四、事实与细节
- [ ] 数量分档咬合：N件=X+Y+Z，两处出现必须一致
- [ ] 术语统一：分级/分类只用一种写法，不混用两套
- [ ] 档位无断层（或注明"这批没落到断档里"）
- [ ] 账目：预付、扣减、余额每次写明确

## 五、叙述风格与视角
- [ ] **禁"第X章"**：人物视角里不许出现章节号，时间一律纯汉字（"第九天见面"，不用"D9"）
- [ ] **禁英文/拼音/字母缩写**：正文和细纲一律汉字（第十一章，收束，标识；甲类/乙类/丙类；T恤→短袖）
  - 例外：剧情核心代号（以设定集为准）、时间数字 19:39:52 保留半角
- [ ] **智商≠预知未来**：每个判断必须有前文依据链（示例格式：
  拒绝上门 ← 第N章定的规矩＋第N-2章问过住址；
  识破试探 ← 前文新痕迹＋天气记录＋前一章的异常）
- [ ] 推理不许跳步："赶工"只能推出"时间紧"，推不出"存量少"（除非有前文数据支撑）
- [ ] 重生/前世经验必须标明，不能写成"本世已验证"（本世时间线才到第N天）
- [ ] 空间几何：俯视、隔窗对视等必须符合物理可能；不行就换合理的观测点

## 六、每章固定动作（流程）
1. **读梗概**：写第N章前，通读`章节梗概.md`中1至N-1章（防历史丢失）
2. 细纲 → 模型A预审（带1-N章全历史）→ 修FIX → grep验证
3. 模型B写初稿 → 自查（本清单）→ 修
4. 双模型评审（带全历史）→ 修FIX → grep验证
5. 定稿 → 同步终审版文件 → **同步更新章节梗概.md**
6. grep 最终验证：人名旧写法、第X章、英文缩写、金额禁词、空降时间等关键词

## 七、grep 验证命令模板
```bash
# 人名（示例：已统一为"老章"，查旧写法应无）
grep -n "老张" 第X章v1.md  # 应无
# 视角（"第X章"字样除标题外应无）
grep -n "第[一二三四五六七八九十\d]*章" 第X章v1.md  # 标题除外应无
# 英文（应无）
grep -n "[a-zA-Z]\{3,\}" 第X章v1.md  # 应无
# 资金口径（按你项目的禁词替换）
grep -n "尾款\|银行App" 第X章v1.md  # 应无
# 时间空降（核对是否为实测）
grep -n "凌晨" 第X章v1.md
```
