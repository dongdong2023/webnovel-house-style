# 每周调研工作流

> 可配合 agent 的定时任务功能每周自动执行（如每周一 09:00；ZCode 用内置定时任务，Claude Code 用 cron / launchd / Task Scheduler），也可以随时手动触发（对 AI 说"跑一轮周调研"）。
> 目的：让家规跟着市场、工具、平台审核规则一起进化，而不是写完就冻结。

## 三条调研线

### 线1 · 市场调研（按你的题材替换关键词）

目的：题材热度、爆款套路、平台政策变化。

搜索角度（每周挑 2–3 个，轮换）：
- 目标平台（番茄/起点/晋江……）你的品类 热门 新书（限近 30 天）
- 品类新标签/新流派（以末世囤货文为例：异能、空间、基建、无CP变体、规则怪谈融合）
- 平台 AI 内容声明/审核 政策变化

产出：热度标签增减、新书案例（书名＋标签＋简介套路）、平台政策变化警示。

### 线2 · AI 写作技巧

目的：长篇 AI 写作的流程与工具改进。

搜索角度：
- LLM 长篇小说 连贯性/伏笔管理/多模型协作 新方法
- GitHub 生态新仓库与大更新。**备用通道**（不受搜索引擎配额限制）：
  `curl -s -G "https://api.github.com/search/repositories" --data-urlencode "q=chinese novel skill" --data-urlencode "sort=updated" --data-urlencode "per_page=8"`
  以及 `q=网文` 同查一遍（中文查询用 Python urllib 发，避免命令行编码问题）
- 网文创作方法论讨论（开篇、节奏、人设、断章钩子）

产出：可落地的流程改进点，注明来源链接。

### 线3 · 去AI味与人味写作研究

目的：了解 AI 文本的典型特征（检测器与编辑盯什么），反推写作规范，把字写得像人。

搜索角度：
- 各平台 AI 检测、审核、判定经验的公开讨论
- AI 文本检测特征（中文）：句长方差、高频虚词、结构模板、标点习惯
- 人味写作/去AI味新技巧、新黑名单词

产出：新禁词/句式候选（给出进检查清单的建议 diff）、写作规范更新。

## 归档与回写

1. 每轮结果写 `references/周报/YYYY-MM-DD_周调研.md`：三条线各一节（要点／来源／对家规的影响），末尾"本周建议"小结。
2. 回写规则（重要结论才动正文文档，平时只归档）：
   - 新黑名单词/句式 → 周报里给出 `检查清单.md` 的具体修改建议，**作者确认后**再改
   - 题材大变化 → `爆款趋势调研.md` 追加"YYYY-MM 动态"一节
   - 平台政策/AI 审核变化 → 周报置顶警示
3. `周报/` 是个人数据，建议不进仓库（本仓库的 .gitignore 已排除 `references/周报/`）。

## 失败处理

- 搜索接口配额/限流：在周报记录失败原因与预计恢复时间，该线本周跳过，**不编造内容**。线2 可用 GitHub API 备用通道照常跑。
- 全部通道失败：写一行失败记录即可，汇报时说明，不要反复重试。
